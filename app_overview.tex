\section{Introduction}

This document provides a comprehensive overview of the AI Toy Companion application architecture, focusing on the secure payment processing and AI service integrations. The application is built as a React Native mobile application with Supabase backend services.

\section{Architecture Overview}

\subsection{Application Stack}
\begin{itemize}
    \item \textbf{Frontend}: React Native (TypeScript)
    \item \textbf{UI Framework}: Gluestack UI
    \item \textbf{Backend}: Supabase (PostgreSQL Database, Authentication, Edge Functions)
    \item \textbf{Payment Processing}: Stripe via Supabase Edge Functions
    \item \textbf{AI Services}: LLM, TTS, STT, Whisper.cpp integration
\end{itemize}

\subsection{Security Architecture}
The application follows a security-first approach with sensitive operations handled server-side:

\begin{itemize}
    \item \textbf{Stripe Secret Keys}: Handled exclusively via Supabase Edge Functions
    \item \textbf{Authentication}: Managed by Supabase Auth
    \item \textbf{Data Storage}: Secured via Supabase Row Level Security (RLS)
\end{itemize}

\subsection{Security Implementation}
\begin{itemize}
    \item \textbf{Client-Side}: Only handles public Stripe publishable key
    \item \textbf{Server-Side}: All secret key operations via Edge Functions
    \item \textbf{Communication}: Encrypted via HTTPS
    \item \textbf{Authentication}: JWT tokens for API calls
\end{itemize}

\subsection{Edge Functions Implementation}
Three Edge Functions handle Stripe operations:
\begin{enumerate}
    \item \texttt{create-payment-intent}: Creates payment intents using secret key
    \item \texttt{confirm-payment}: Verifies payment status
    \item \texttt{process-refund}: Handles refund operations
\end{enumerate}

\section{AI Service Integrations}

\subsection{AI Service Integrations}

\subsection{Current Implementation}
\begin{itemize}
    \item \textbf{STT (Speech-to-Text)}: Google Speech-to-Text API via Supabase Edge Function
    \item \textbf{LLM (Large Language Model)}: Google Gemini API via Supabase Edge Function
    \item \textbf{TTS (Text-to-Speech)}: Resemble AI API via Supabase Edge Function
    \item \textbf{All API Keys}: Stored securely in Supabase Edge Function environment variables
\end{itemize}

\subsection{Audio Processing Architecture}
The audio processing happens in a distributed manner:
\begin{itemize}
    \item \textbf{Recording}: Toy microphone captures audio
    \item \textbf{Transmission}: WAV chunks sent to mobile app via Bluetooth
    \item \textbf{STT Processing}: Mobile app sends audio to Supabase Edge Function (Google STT)
    \item \textbf{LLM Processing}: Transcribed text sent to Supabase Edge Function (Gemini)
    \item \textbf{TTS Processing}: LLM response sent to Supabase Edge Function (Resemble)
    \item \textbf{Playback}: Generated audio chunks sent back to toy speaker via Bluetooth
\end{itemize}

\section{Data Flow}

\subsection{User Interaction Flow}
\begin{enumerate}
    \item User speaks into toy microphone
    \item Toy captures audio and sends WAV chunks to mobile app via Bluetooth
    \item Mobile app accumulates chunks and sends to Supabase Edge Function (STT)
    \item Google Speech-to-Text transcribes audio to text
    \item Text sent to Supabase Edge Function (LLM)
    \item Google Gemini generates AI response
    \item Response sent to Supabase Edge Function (TTS)
    \item Resemble AI converts text to speech (WAV format)
    \item Mobile app receives audio and sends chunks to toy via Bluetooth
    \item Toy speaker plays audio response
\end{enumerate}

\subsection{Toy Connection Flow}
\begin{enumerate}
    \item Mobile app connects to toy via Bluetooth Low Energy (BLE)
    \item Custom personality/mode settings applied
    \item Mobile app subscribes to audio RX characteristic (receives from toy microphone)
    \item Mobile app prepares audio TX characteristic (sends to toy speaker)
    \item Conversation context maintained throughout session
    \item Interaction data stored in Supabase
\end{enumerate}

\section{E-commerce Flow}

\subsection{Shopping Experience}
\begin{enumerate}
    \item User browses products in Marketplace
    \item Products added to cart (stored in Supabase)
    \item Checkout initiated via Stripe integration
    \item Payment processed securely via Edge Functions
    \item Order confirmed and stored in Supabase
\end{enumerate}

\subsection{Cart Management}
\begin{itemize}
    \item Cart items persisted in Supabase database
    \item Real-time synchronization across devices
    \item Secure payment processing
\end{itemize}

\section{Answers to Client Questions}

\subsection{Stripe Security Confirmation}
\textbf{Yes}, all Stripe secret keys are handled server-side via Supabase Edge Functions and not directly in the mobile app:
\begin{itemize}
    \item Mobile app only uses public publishable key
    \item All secret key operations (payment intent creation, confirmation, refunds) handled by Edge Functions
    \item Payment processing occurs securely via Stripe SDK with client secret obtained from server
\end{itemize}

\subsection{STT Processing Location}
\textbf{Updated Architecture}: Audio recording happens on the toy hardware, not the mobile app:
\begin{itemize}
    \item Toy microphone captures audio
    \item Audio sent as WAV chunks to mobile app via Bluetooth
    \item Mobile app forwards audio to Google Speech-to-Text via Supabase Edge Function
    \item Transcribed text processed by Gemini LLM via Supabase Edge Function
    \item Response converted to speech by Resemble AI via Supabase Edge Function
    \item Audio chunks sent back to toy speaker via Bluetooth
\end{itemize}

\textbf{Key Change}: Whisper.cpp has been removed. All processing now uses cloud services via Supabase Edge Functions for better accuracy and reliability.

\section{Future Requirements}

\subsection{AI Service Keys Needed}
All API keys are now configured in Supabase Edge Functions (not in mobile app):
\begin{itemize}
    \item \textbf{Google Speech-to-Text API Key}: For audio transcription (GOOGLE\_STT\_API\_KEY)
    \item \textbf{Google Gemini API Key}: For LLM responses (GEMINI\_API\_KEY)
    \item \textbf{Resemble AI API Key}: For text-to-speech (RESEMBLE\_API\_KEY)
    \item \textbf{Resemble Project ID}: For TTS project configuration (RESEMBLE\_DEFAULT\_PROJECT\_ID)
    \item \textbf{Resemble Voice ID}: For TTS voice selection (RESEMBLE\_DEFAULT\_VOICE\_ID)
\end{itemize}

\textbf{Configuration Location}: Supabase Dashboard → Edge Functions → Secrets

\section{Conclusion}

The AI Toy Companion application has been architected with security and scalability as top priorities. The payment processing properly handles secret keys server-side through Supabase Edge Functions, meeting all security requirements.

The voice processing pipeline has been updated to support toy-based audio recording:
\begin{itemize}
    \item \textbf{Audio Recording}: Toy microphone captures audio and sends WAV chunks via Bluetooth
    \item \textbf{STT Processing}: Google Speech-to-Text via Supabase Edge Function
    \item \textbf{LLM Processing}: Google Gemini via Supabase Edge Function
    \item \textbf{TTS Processing}: Resemble AI via Supabase Edge Function
    \item \textbf{Audio Playback}: Toy speaker receives audio chunks via Bluetooth
\end{itemize}

All API keys are securely stored in Supabase Edge Function environment variables, with no sensitive credentials in the mobile application. The architecture is production-ready and requires only API key configuration in the Supabase Dashboard to activate all services.
